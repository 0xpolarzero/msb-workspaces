Silo · Log viewer research

Logs should behave like a native data browser, not a centered text poster.

The current screen has the right raw ingredients—workspace filters, monospaced messages, and copy—but the interaction hierarchy is wrong. Mature desktop log tools use a dense, top-aligned row model with native selection, search, context actions, and structured details.

Recommendation: replace the single text document with a native macOS table. Keep message text selectable, make rows selectable with standard click / Shift-click / Command-click, and provide Copy Selected plus Copy Visible. Use a details inspector for pretty JSON instead of expanding large payloads inline.

Why the current screen looks wrong

1

No scan structure

A large undifferentiated text block gives the eye no stable timestamp, source, severity, or message columns. Even aligned monospace text reads like terminal output rather than an inspectable macOS data view.

2

Actions are detached

The line count and copy button float far away from the content. Mature tools keep search, wrap, follow, and copy controls in one compact toolbar immediately above the rows.

3

Selection is ambiguous

Text dragging is useful for fragments, but it does not replace row selection. A desktop viewer should support both native text selection and native multi-row selection.

4

Structured data dominates

Pretty-printing JSON directly in the stream makes rows unexpectedly tall. Established viewers keep the stream compact, then reveal structured fields in a side panel or expandable details view.

5

Data quality leaks through

Heartbeat characters, probe ports, and partial JSON delimiters destroy trust. Transport cleanup must happen before rendering; the viewer should never be responsible for making protocol debris look acceptable.

6

No operational rhythm

Logs normally need search, pause/follow, wrap, clear, context, and level/source filters. A static text surface cannot communicate whether it is live, paused, filtered, or complete.

Click selects one row. Shift-click selects a range. Command-click toggles rows. Dragging inside the message selects text. Double-click or Return opens details. Right-click exposes Copy Message, Copy Row, Show Context, Include Workspace, and Exclude Workspace.

Copy behavior

Native text copy

Users drag across message text and press ⌘C. This is best for fragments and should work without entering a special mode.

Native row copy

Click, Shift-click, and Command-click use standard macOS table selection. ⌘C copies selected rows as aligned plain text.

Copy Visible

Copies the current filtered result set—not hidden workspaces and not lines outside the current query. Label it explicitly.

Structured copy

The detail inspector offers Copy Message, Copy JSON, and Copy Row with timestamp and workspace metadata.

Data contract required

The current model discards per-line timestamps. The adapter emits observedAt, but SiloLogEntry only retains workspace, message, and display safety. A credible table needs at least timestamp, workspace, message, and optional severity/source. Preserve timestamp before redesigning the table; otherwise it cannot sort or merge workspace streams correctly.

Implementation sequence

  1. Fix the stream contract. Preserve per-line timestamps; classify and suppress internal transport/probe noise before it reaches the model.
  2. Build a native table. Columns: Time, Workspace, Message. Use a selection set and standard macOS multi-selection behavior.
  3. Add the compact toolbar. Search, Follow/Pause, Wrap, Copy Selected, Copy Visible. Keep workspace chips in the shared workspace filter row.
  4. Add row affordances. Hover copy action and context menu; no persistent icon clutter.
  5. Add structured details. Inspector/flyout with pretty JSON, raw message, metadata, and copy variants.
  6. Then optimize. Keep the latest bounded window in memory, preserve scroll position, and only auto-scroll while Follow is enabled.

What not to do

AvoidOne centered text document with controls at opposite edges.
AvoidCheckbox/circle selection controls permanently attached to every row.
AvoidPretty-printing every JSON payload inline by default.
AvoidCalling copied data “all” when it is actually filtered or bounded.
PreferDense native table, ordinary macOS selection, clear copy scope, and a details inspector.
