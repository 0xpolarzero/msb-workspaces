Product and technical plan · 2026-08-07

Silo

A small native macOS menu-bar monitor and launcher for the three persistent MicroSandbox workspaces: dev, playgrounds, and personal.

Core decision: build a monitor and launcher, not a graphical replacement for silo. Keep the status bar calm, expose frequent reversible actions directly, and hand credential-heavy, destructive, or parameter-heavy work back to the trusted CLI in Ghostty.

1. What the repository tells us

Three isolated trust domains

dev is the main workspace, playgrounds is for experiments, and personal is for personal projects. Each has its own VM, persistent ext4 workspace volume, Docker runtime volume, processes, credentials, network, loopback IP, and browser hostname.

Current resource limits

Packaged defaults allocate 8 CPU / 32 GB to dev, 4 CPU / 32 GB to playgrounds, and 6 CPU / 16 GB to personal. Resize ceilings are 12 CPU and 48/48/32 GB respectively.

Safety boundary

Guest GitHub access is read-only. Host-only pushes use a separate Keychain credential. Failed credential cleanup can quarantine a workspace; normal start, restart, exec, SSH, and push paths then fail closed.

Useful runtime facts

MicroSandbox exposes stable JSON for status, inspect, and metrics. The current silo status table and silo metrics watch output are human-oriented and should not be parsed by the app.

2. Recommended product shape

Menu-bar icon

One monochrome SF Symbol, such as square.stack.3d.up. Never put workspace names, CPU, memory, or action icons in the menu bar.

  • Normal: neutral template icon.
  • Attention: small amber indicator.
  • Critical/offline: red indicator.
  • Busy: restrained progress treatment, never an attention-grabbing animation.

Tooltip: “silo — all systems normal”, or the highest-priority issue.

Popover

Use a compact, keyboard-navigable window around 380–400 pt wide. Header contains silo, aggregate state, Refresh, Settings, Activity, and Quit. Scroll only the workspace list; keep the header and footer stable.

Workspace cards

One card per workspace, in fixed order. Show purpose, lifecycle state, last-updated time, CPU, memory, and the single best next action. Keep secondary actions in a labeled menu.

Detail window

Open a normal window for data-rich work: Overview, Metrics, Logs, Repositories, Ports, and Maintenance. Recommended initial size: roughly 760×520 pt. Do not turn the popover into a terminal emulator.

Popover interaction

  • Stopped: primary action is Start; show “Stopped” rather than treating it as an error.
  • Running: show CPU and memory bars; primary actions are Open site and Open in Zed, with Stop and Restart in the workspace menu.
  • Starting / stopping / restarting: disable conflicting controls, show a labeled progress state such as “Starting dev…”, and refresh when the process exits.
  • Unavailable: preserve the last good snapshot with a stale timestamp, show Retry, and leave other workspace cards usable.
  • Quarantined: show the stored reason prominently; disable SSH-derived actions and offer only GitHub repair / terminal fallback. Never clear the marker directly from the app.
  • Do not automatically start stopped VMs during polling, app launch, metrics refresh, or opening the popover.

4. SwiftUI and macOS architecture

Recommendation: use a SwiftUI-first agent app targeting macOS 14+, with MenuBarExtra and .menuBarExtraStyle(.window). This is Apple’s native path for a menu-bar-only utility with a popover-like window and standard SwiftUI controls. Keep the process and state boundaries Foundation-only so a tiny AppKit bridge can be added later if a concrete MenuBarExtra limitation appears.

App shell

@main app with MenuBarExtra, .menuBarExtraStyle(.window), an agent-style LSUIElement bundle setting, a Settings scene, and a separate detail window opened only when needed.

State and concurrency

Use an @MainActor AppModel backed by an SiloClient actor. Give each workspace an operation lock and a cancellable operation state. Status and metrics reads can run in parallel; conflicting writes cannot.

Process boundary

Launch absolute executable paths with Foundation.Process and an argument array. Set a deterministic PATH containing $HOME/.local/bin, Homebrew, and system paths. Preserve HOME so silo finds ~/.config/silo/config.sh.

Distribution

For a personal utility, prefer a Developer ID/notarized distribution outside the Mac App Store and do not enable App Sandbox initially. The app must execute the user’s installed CLI, launch Ghostty/Zed, read selected files, and participate in normal Keychain prompts.

Command adapter contract

Current safe path: invoke silo for all policy-bearing mutations and terminal handoffs. For read-only telemetry, use msb status --all --label silo.managed=true --format json, msb inspect NAME --format json, msb metrics --all --format json or --follow, and silo logs NAME --json --follow. Do not parse silo status tables or silo metrics --watch terminal output.

Add a small versioned machine-readable surface to silo before production UI work:

  • silo status --format json: schema version, Silo/MSB versions, workspace IDs, lifecycle state, resource configuration, hostnames/IPs, published ports, GitHub credential presence/access mode, verification metadata, quarantine state, capabilities, and timestamp. Never include token values.
  • silo metrics [TARGET] --format json --once and --follow: preserve the existing human default while exposing a stable JSON contract.
  • silo github status --format json, silo repos WORKSPACE --format json, and silo ports [TARGET] --format json.
  • Later: structured preview/result modes for push, backup, restore, and disk. Until then, keep those workflows terminal-visible.

This avoids sourcing or parsing config.sh in Swift and avoids coupling the app to MicroSandbox’s incidental JSON fields. Human CLI output remains unchanged.

5. Polling, freshness, and notifications

Status cadence

Read status immediately on launch and when the popover opens. Poll every 10–15 seconds while the app is active. Background polling must never call a command that starts a VM.

Metrics cadence

Show compact metrics from the latest snapshot. Stream or poll every 2–5 seconds only while the detail Metrics view is visible; stop the stream when it closes.

Stale data

Every field has an observed-at timestamp. On failure, preserve the last good value with a visible Stale badge and Retry. Never convert a transport error into “Stopped”.

Notifications

Request notification permission only from an explicit Settings toggle. Notify only after an initial baseline and only for deduplicated meaningful transitions or failed long-running operations. Suppress alerts caused by the app’s own action.

6. Safety and UX guardrails

RiskGuardrail
Accidental lifecycle interruptionUse distinct Start, Stop, and Restart buttons. Disable conflicting actions while busy. Confirm Stop/Restart and require stronger confirmation for global operations.
Host-only pushShow exact repository, path, branch, SHA, fast-forward mode, and commits. Preserve the CLI’s PUSH phrase; never auto-approve or hide force-with-lease.
Credential leakageNever log environment values, Keychain contents, token prompts, or raw command environments. Keep GitHub setup in a terminal until a secure native wizard is explicitly designed.
Quarantine bypassUse silo, not direct msb, for mutations. Model quarantine separately from lifecycle state and do not offer a “clear quarantine” button.
Destructive Docker cleanupDefault to volume-preserving cleanup. Make --volumes a separate, red, explicitly confirmed option.
Cold backup surprisesBefore execution, show destination, sensitive contents, affected workspaces, and that running VMs will be stopped and then restored to their prior running set.
Restore damageKeep restore out of the popover. Require checksum validation, archive inspection, typed RESTORE, and a final explanation that VMs remain stopped and Keychain tokens are not changed.
Untrusted arbitrary executionTerminal-first for exec. If a native form is later added, pass validated argv and never interpolate a user string into a shell command.
Accessibility and localizationUse native Label/Button/Menu/Picker/TextField/SecureField/Toggle/ProgressView controls, visible text beside icons, VoiceOver labels that include workspace and state, keyboard focus order, semantic status text, and locale-aware FormatStyle APIs. Put strings in Localizable.xcstrings.

7. Delivery phases

0

Stabilize the machine interface

Add and test versioned JSON modes for status, metrics, GitHub status, repositories, and ports. Add fixture-based parser tests and preserve current human output. This is the prerequisite that prevents a brittle Swift text parser.

1

Ship the monitor core

Create macos/SiloMonitor as a macOS 14+ Xcode app. Implement the status item, three cards, status/metrics polling, Start/Stop/Restart, Refresh, settings, login item toggle, errors, stale data, Activity, and terminal fallback.

2

Ship daily workflow launchers

Add Open site, Copy URL, Open in Zed, Ghostty shell handoff, ports picker, streaming logs, repository picker, clone, pull, and GitHub status/verify. Add the detail window and bounded operation history.

3

Ship guarded maintenance

Add disk inspection, resize, backup, tunnel tracking, deep check, push review, and identity settings. Keep operations visible with progress and failure recovery.

4

Ship recovery and expert controls

Add secure native flows only where they improve safety: clean, upgrade, update, host repair, GitHub setup/remove, restore, and optional canned exec actions. Terminal handoff remains a supported escape hatch.

8. Verification plan

Pure Swift tests

  • JSON decoding and schema-version rejection.
  • Lifecycle transition/state-machine invariants.
  • Stale/partial data aggregation and status-item severity.
  • Argument construction and path validation.
  • Redaction and bounded output buffers.
  • Confirmation policy for every dangerous command.

Process integration tests

  • Fake silo/msb executables with controlled stdout, stderr, exit codes, delays, and streamed JSON Lines.
  • Cancellation terminates child processes without launching duplicate operations.
  • Missing CLI/config, missing Keychain access, quarantine, and stale data all render recoverable states.

Real Mac smoke test

  • Launch with all VMs stopped; verify no automatic starts.
  • Start dev, observe readiness and metrics, open a published site, open Zed and Ghostty, then stop.
  • Stream logs, run quick check, verify GitHub status, and exercise a failed command.
  • Test light/dark mode, VoiceOver, keyboard focus, notification opt-in, login item, signed build, and relaunch.
Do not use production backup/restore, credential rotation, force push, or destructive Docker cleanup as casual smoke tests. Cover their command planning and confirmation behavior with fakes; use a disposable workspace for real end-to-end validation.

9. Decisions to keep fixed unless a concrete need appears

  • macOS 14+ deployment target; SwiftUI MenuBarExtra with window style.
  • One calm icon; no status text or workspace names in the menu bar.
  • No automatic VM starts from monitoring.
  • silo remains the policy boundary for mutations.
  • No App Sandbox for the first personal Developer ID build.
  • No global hotkey, arbitrary command form, or token wizard in the first release.
  • Settings persist only non-sensitive preferences: paths, favorites, polling, notifications, launch-at-login, and display choices.

Research panel

Seven independent gpt-5.6-sol research runs reviewed command inventory, SwiftUI/AppKit architecture, menu-bar UX, accessibility, safety, integration feasibility, and product prioritization. They made no repository code changes. Their convergent recommendations are reflected above: use silo for policy-bearing mutations, machine JSON for telemetry, progressive disclosure, explicit confirmations, stale-data semantics, and terminal fallback for sensitive workflows.
