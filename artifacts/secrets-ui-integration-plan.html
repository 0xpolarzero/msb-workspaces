Secrets in MSW Monitor

Placement, interaction, and runtime integration for host-held API keys.

Decision: add a top-level Secrets tab.

Put it between GitHub and Notifications. Secrets are cross-workspace host policy, so they do not belong inside one workspace or under General. Do not add another macOS application-menu item or status-popover shortcut.

Accept exact hosts, *.example.com, and *. No schemes, paths, or ports. Explain: “The real value is inserted only into HTTPS requests to these domains.”

* is allowed but requires confirmation: any code in the VM could send this credential to any HTTPS server.

On edit, never load the existing value back into the form. Offer Replace value. Keep the name fixed; changing a name is remove plus add.

Status and restart behavior

  • Add: Pending addition → Restart required.
  • Edit: Disable the old binding immediately, stage the replacement → Restart required.
  • Remove: Disable substitution immediately, retain only enough state to verify cleanup → Removal pending restart.
  • Stopped workspace: show Applies on next start instead of offering Restart.
  • Failure: show Error with Retry; never report Active until MSW verifies the runtime binding.

The Workspaces tab and status popover should show a small Restart required indicator for affected workspaces and reuse the existing reviewed restart confirmation.

  1. Add AppTab.secrets, route/deep-link support, and a separate SecretsView.swift; do not grow the already-large SettingsView.swift with secret logic.
  2. Add typed msw app secrets-list, secret-plan, and secret-apply commands. The app sends new values through stdin, never argv or environment.
  3. The CLI stores values in macOS Keychain and stores only names, workspace scopes, domains, generation, and pending state in the metadata file.
  4. Every MSW start/restart reads active Keychain values and exports them only to the child msb process long enough to resolve NAME@HOSTS. This extends the existing single lifecycle boundary instead of adding an app-only start path.
  5. Extend workspace state with a separate secret-configuration restart reason. Do not reuse the GitHub credential state.
  6. Verify add/edit/remove, exact and wildcard domains, * confirmation, Keychain/backup exclusion, placeholder-only guest visibility, blocked disallowed-host requests, deep linking, tab layout, and restart badges.
