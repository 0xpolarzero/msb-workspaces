Onboarding feels unstable and unclear

The screen reacts to background work instead of staying calm and predictable.

  1. Loading states are wrong. Refreshing GitHub also makes the Apply button say “Applying…”.
  2. Unrelated controls freeze. A refresh disables repository choices, Apply, and account management.
  3. The layout jumps. Buttons, messages, progress rows, and the main action appear, disappear, and change width.
  4. Progress appears in the wrong place. A small refresh changes the whole section instead of only the Refresh control.
  5. There are too many confirmation clicks. GitHub needs Apply, then Continue. Identity needs Save, then Review setup.
  6. “Optional” is inconsistent. Skip GitHub disappears once an account is connected, even when no repositories are found.
  7. Disabled actions are unexplained. Continue can be blocked by hidden background work with no clear reason.
  8. The wording is too technical. Terms such as VM, host credential, repository policy, and verification make first-time setup harder.
  9. The final review is misleading. It says choices are “ready to apply” after some choices were already applied.
Main cause: GitHub connect, refresh, and apply all share one loading flag. The UI cannot tell which action is actually running.

Basis: current SetupView.swift behavior plus the native onboarding UI flow. The current fixture values are deterministic test data, not live sandbox telemetry.
