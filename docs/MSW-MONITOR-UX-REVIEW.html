MSW Monitor · Product UX review

Make every workspace action trustworthy, recoverable, and obvious.

The review found several trust gaps, then the implementation pass closed the highest-risk contracts: health now waits for an authoritative baseline, destructive GitHub changes require scoped review, Connect-to-Apply retains verification results, and workspace scope/capabilities are explicit. Remaining work is concentrated in start-and-open compound actions, per-section loading/navigation polish, backup preflight detail, accessibility, and the deployment-supplied GitHub App installation link.

Review date: 2026-08-11 Verification refreshed: 2026-08-14 8 parallel Sol audits Implementation + evidence pass Native macOS app

Executive verdict

Prioritize trust before polish. The implementation pass now closes the most consequential trust breaks: cold launch reports “Not observed,” destructive GitHub revocation is reviewed and phrase-gated, Connect-to-Apply commits only after verification, and detail routes carry workspace scope. The remaining contract gaps are narrower: stopped-workspace start-and-open actions, backup preflight/rollback detail, per-section request state, and inclusive interaction polish.

The fail-closed model and transactional services are now surfaced more honestly through health states, freshness/quarantine reasons, operation phases, verification summaries, notification categories, and deep links. The report below marks each original finding as shipped, partial, or open instead of presenting the pre-remediation review as current behavior.

North-star journey

The app should guide a developer from “What is this?” to “I know exactly what is safe to do next,” without forcing them to infer state from colors, hidden scope, or raw implementation terms.

01

Welcome

Explain the three isolated workspaces, resource model, and trust boundary.

02

Check

Preflight the Mac; disclose admin, host-helper, VM, and time effects.

03

Verify

Install and verify MSW with live phase, elapsed time, and retry-from-phase guidance.

04

Access

Optionally connect GitHub with explicit per-workspace guest-read and host-write scopes.

05

Identity

Collect Git identity and show what will be configured where.

06

Finish

Show a final recap; only an explicit Done marks onboarding complete.

07

Operate

Show one health headline, one best next action, and persistent workspace scope.

08

Recover

Preserve last-known state and pair every problem with a safe, specific recovery action.

This sequence follows the product intent in docs/MSW-MONITOR-MACOS26-OAUTH.plan.md:169-261 and the daily tasks documented in docs/SETUP-GUIDE.md:67-299.

P0 — Fix trust and safety contracts first

These issues can make a user believe the wrong thing, act on the wrong workspace, or trigger a destructive security operation without an adequate review.

1. Never say “Ready” before an authoritative baseline

P0

Fixed. Cold launch remains not observed; aggregate health distinguishes not observed, unavailable, stale, quarantined, recovery-required, refreshing, and ready. Observation count advances only in fixture mode or after a successful remote observation.

ImplementedAppModel.swift:331-423, 425-440 derives health from authoritative observation and freshness, while MonitorView.swift:66-104 and StatusBarController.swift:164-179 consume the same model. The native smoke path asserts Not observed before refresh.

Status: Shipped and covered by the native model/UI verification. Remaining work is accessibility announcement/focus polish, not the Ready-before-baseline contract.

2. Put a reviewed confirmation boundary around GitHub revocation

P0

Fixed. Workspace removal and account disconnect now open a scoped impact review, list affected owners/repositories, explain VM-held and service-grant effects, preserve quarantine on uncertain cleanup, and require an exact phrase.

ImplementedSettingsView.swift:141-151, 365-397, 646-748 provides the sheet, impact list, credential effects, workspace-name phrase, and DISCONNECT phrase. GitHubAuthorizationCoordinator.swift:647-728 performs ordered cleanup and typed recovery.

Status: Shipped. The destructive boundary is now explicit before any revocation or local credential mutation.

3. Do not mark onboarding or access complete without verification

P0

Fixed. Connect-to-Apply requires valid reviewed assignments and runs verification before returning committed metadata. Setup retains per-workspace verification and lifecycle-restoration results, blocks completion until the GitHub decision, identity decision, and verification gate are satisfied, and exposes a deliberate Done action.

ImplementedGitHubAuthorizationCoordinator.swift:315-595 journals grant creation, verifies scope/lifecycle, and rolls back or quarantines on failure. SetupView.swift:932-965, 1786-1797 renders retained results and gates completion.

Status: Shipped for the reviewed assignment flow. Live service/browser issuance remains an environment prerequisite documented in Verification and limits.

4. Make workspace scope and capabilities impossible to miss

P0

Fixed. Details no longer silently defaults to dev; every route carries an optional workspace and section, and scoped sections refuse to act until a workspace is chosen. Server action capabilities, reasons, and recovery text now reach the model and card gates.

ImplementedDetailView.swift:43-82, 126-145, 260-295 defines typed routes and a persistent workspace picker. AppModel.swift:1003-1050 and MonitorView.swift:207-249 enforce capability/freshness/quarantine safety at both model and UI boundaries.

Status: Shipped. Remaining navigation polish is tracked under finding 8.

6. Turn every failure into a next action

P1

Partial. Recovery context now carries cause, affected scope, recovery text, freshness, quarantine state, and verification age into monitor, setup, details, and notification surfaces. Some settings states and background operation errors still need a single primary action and consistent focus transfer.

7. Replace “start first” friction with truthful compound actions

P1

The documented CLI auto-starts a stopped workspace for terminal, Zed, and site entry, but the app disables all three unless already running. “Open Terminal” appears as passive next-action text rather than the useful primary button. Site is fixed to port 3000.

ObservedMonitorView.swift:170-212 gates actions on running/fresh state. AppModel.swift:214-299 rejects stopped workspaces. The documented behavior is in docs/MSW-CHEATSHEET.md:171.

Change: make the card’s best next action a button. Use “Start dev and open Terminal,” “Start and open in Zed,” and “Start and open site,” each with an effect preview and progress. Add project-path and favorite/active-port selection; retain a separate no-start URL probe.

8. Make Details and Settings one coherent navigation system

P1

Partial. Typed deep links, workspace/section routes, a persistent Details picker, and cached-content/error language are implemented. The separate native Settings scene and custom Settings window remain, and independent detail sections still share more request state than ideal.

ImplementedDetailView.swift:43-82, 260-325 carries scope and section; SettingsView.swift:108-151 centralizes tab navigation but the app still exposes both Settings presentation paths. DetailView.swift:702-728 preserves cached context on failure.

Status: Partial. Remove duplicate Settings presentation and give each detail section isolated loading/error/freshness state.

9. Make backup and restore honest and reviewable

P1

Partial. Backup now discloses sensitive archive scope, separates destination selection from execution, shows running-workspace effects, and requires an explicit restore review plus RESTORE phrase. Required free space, pre-apply checksum validation, and structured rollback proof remain unavailable in the runtime contract.

ImplementedDetailView.swift:558-645, 731-782, 1074-1155 provides archive scope, review dialogs, stop/restart result lists, and unknown-outcome warnings. AppModel.swift:860-959 reconciles backup restart sets and restore observations.

Status: Partial. Add capacity/checksum/rollback metadata when the service exposes it; never imply a stronger restore guarantee than the runtime proves.

10. Make GitHub setup explicit, resumable, and safe

P1

Partial. Setup now resumes drafts, preserves existing access on cancellation, requires an explicit GitHub decision and identity decision before Done, prevents incomplete enabled assignments from reaching Apply, and retains verification results. The access-mode label still needs a clearer guest-read/host-write product name, and the installation URL is a deployment input rather than a checked-in release value.

ImplementedSetupView.swift:341-375, 1248-1264, 1786-1797, 1960-1990 gates completion, validates drafts, persists resume state, and clears it only on Done. docs/GITHUB-SETUP.md:25-39 documents the safe installation-link boundary.

Status: Partial. Rename access modes for trust clarity and provide the approved installation URL in the signed/release build.

11. Add opt-in background notifications with deep links

P1

Fixed. Notification categories are opt-in, permission is requested only when a category is enabled, events are deduplicated by kind/workspace/generation, retries are bounded, and deep links target the affected workspace or section without secret material.

ImplementedNotificationCoordinator.swift:5-35, 146-203, 252-356 owns category preferences, authorization, dedupe, retry, and payload construction. AppModel.swift:610-618, 1251-1288, 1446-1469 emits sustained-unavailability, quarantine, lifecycle, credential, backup, and operation events.

Status: Shipped. Remaining work is accessibility/UX polish for category settings and test coverage for every notification trigger.

What is already working

Safety foundations

Quarantine and freshness gates are fail-closed in the model; pending lifecycle/push plans are invalidated when state becomes unsafe. Push and restore require explicit phrases and initially focus Cancel.

Native interaction base

The app uses standard SwiftUI controls, a real status item, a transient production popover, reusable windows, tooltips, keyboard shortcuts for Refresh/Quit, and named workspace accessibility groups.

Unit confidence

The focused unit suite passed 57 tests with zero failures, including authorization, quarantine, stale-plan cancellation, protocol validation, recovery-boundary handling, workspace URL validation, notification delivery, and both all-workspace and single-target identity verification gates.
